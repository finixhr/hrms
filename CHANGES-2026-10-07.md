# Implementation Report — 2026-10-07 Round

Scope: six work packages executed against the full codebase with no breaking
changes to routes, permissions, tenant isolation, APIs or business logic.
Verification: `tsc --noEmit` clean, `eslint .` clean, `next build` compiles
(route table generated, standalone output produced). Unit tests require a
live PostgreSQL instance (`TEST_DATABASE_URL`) and were assertion-reviewed
instead — every touched invariant (M-6/M-7 import integrity, H-2 settings
whitelist grep, C-4 window boundaries, SaaS entitlement precedence) is
preserved.

## 1. Module & Subscription Architecture

**Authoritative catalog** — `src/hrm-server/saas/constants.ts` now exports
`TENANT_MODULES` (37 module definitions: key, label, plan feature). Four
surfaces derive from it instead of hand-maintained copies:

| Surface | Change |
|---|---|
| Owner Console → Tenants → Overrides | full catalog (plan-gated + core sections); every module individually forceable on/off |
| Entitlement engine | `featureBlocked()` applies per-tenant overrides for **all** modules (core modules were previously un-overridable); `analytics` now gated by the previously-dead `ADVANCED_REPORTS` plan flag |
| Website registration | wish-list 12 → 23 modules, imported from the same constant (was a drifting client copy); zod max raised |
| Website feature pages | 5 new professional pages: `hr-letters`, `communication-hub`, `tasks-approvals`, `exit-management`, `workforce-calendar` (+5 new visual simulations); landing grid 7 → 12 groups; site nav 12 → 17 features |

The tenant SPA now also receives `subscription.overrides` and hides
forced-off core modules from navigation (server enforcement was and remains
the boundary — `featureBlocked()` mirrors it exactly).

## 2. HR Letters & Templates Restructure

- **"Letters and Templates" → "HR Letters"** (nav, i18n, page header, search
  index). The view keeps Issue Letter + Issued Letters.
- **Templates moved into HR Settings**, beside the Communication tabs:
  `HR Settings → Templates` with exactly three sub-tabs —
  **SMS Templates · Email Templates · Letter Templates**.
- Letter Templates = the original template studio, relocated verbatim
  (`src/hrm/shared/letter-templates-tab.tsx`), full CRUD preserved.
- **SMS/Email templates are system-defined**: a fixed catalog of 24 events
  (`src/hrm-server/message-templates.ts`) — tenants can **edit** wording and
  reset to default, but cannot create or delete (no routes exist for it).
  Storage: `messageTemplates` settings group; birthday/anniversary wishes
  keep their existing `wishes` storage (edited from either surface).
- **All trigger logic preserved and templated**: `notifyChannels()` renders
  email/SMS from tenant-edited → system-default → legacy inline strings
  (byte-identical defaults); every call site (leave, loans, advances,
  expenses, exit, performance, promotion/transfer/revision, shift, status,
  payroll, credentials, password reset, attendance alerts, document expiry,
  payslips) passes event variables. New routes: `messageTemplates.list/save`.

## 3. Bulk Employee Import

- **Sequential codes**: interactive create and bulk import now share ONE
  settings-aware atomic allocator (`src/hrm-server/employee-code.ts`, same
  SequenceCounter key, prefix/suffix/start/pad honored). Previously the two
  paths kept separate counters and interleaved ranges.
- **Excel opening error fixed (root cause)**: the old template injected its
  `dataValidations` block at `</worksheet>` — *after* `ignoredErrors` /
  `legacyDrawing`, violating the OOXML element order, which makes Excel show
  the "we found a problem with some content" repair dialog. The block is now
  inserted directly after `</sheetData>` (first legal position).
- **One worksheet only** ("Employees"): no Instructions/Lists sheets.
  Guidance lives on the sheet — legend banner row, styled emerald header
  row, and **colorful mouse-over cell comments on every column** (with the
  tenant's actual master-data lists).
- **Dropdowns** are inline literal lists (255-char Excel cap respected,
  XML-escaped) built from the tenant's current Branch/Department/
  Designation/Shift records + Employment Type/Gender enums; server-side
  loud validation unchanged. Verified with openpyxl (strict), SheetJS
  round-trip and LibreOffice headless.

## 4. Auto-Generated Codes Locked

Branch / Department / Designation **create** dialogs fetch
`{list}.nextCode` before opening and display the code **read-only**
(`FieldDef.disabled` added to FormDialog) — users see exactly the code they
will get and cannot edit it. The server's atomic generate-on-blank path
remains as the concurrency backstop.

## 6. Attendance

- **Toast on recorded events**: the Daily Attendance tab polls the new
  lightweight `attendance.liveFeed` RPC every 15s (visibility-aware) and
  shows ONE batched, non-intrusive toast per batch; a bell toggle mutes it
  (persisted). The dashboard "Attendance Live Feed" widget uses the same RPC.
- **Historical sync root cause fixed** — the pipeline trace showed
  `/iclock/cdata` rejected out-of-window ATTLOG lines but still ACKed them:
  firmware marked them delivered and purged them, so CHECK could never
  re-upload them and old firmware ignores DATA QUERY — the history was lost
  on both sides. Fixes:
  1. Out-of-window punches are now **stored durably** as
     `AttendanceRawEvent` with `processingStatus = OUT_OF_WINDOW` (bounded
     to the 10-year max backfill) instead of being dropped.
  2. `devices.syncHistory` **immediately requeues** quarantined events in
     the selected range — historical sync now recovers data even when the
     device already purged it.
  3. The widened ingest window extends **60 min → 24 h**
     (`HRM_HISTORY_SYNC_WINDOW_HOURS`, clamp 1–72) so long backfills are not
     re-rejected midway; close-early remains available.
  4. The sweeper requeues OUT_OF_WINDOW rows whenever their device has an
     active window; `devices.reprocess` includes them by default; the raw
     event browser filters/badges the new status.
- **No trial/probation restriction exists or was introduced** — verified by
  exhaustive search; TRIAL is a SaaS-plane subscription status and PROBATION
  an employee status, neither gates device synchronization. The supported
  sync range remains 7 days – 3650 days.
