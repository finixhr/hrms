## 1. Field Force → Reports → Employee: View Location Hit Map (NEW)

The Reports tab aggregated a whole date range per employee but had no way to
see the trail. Every employee row in **Reports** now carries a
**View Location Hit Map** button:

- click → a compact **date chooser** (defaults to the report's end date,
  min/max clamped to the report range) → **Open Hit Map**;
- opens the same day-replay dialog as the History tab (dotted trail +
  durations of every stoppage) for the chosen employee + day.

Server-side nothing changed — it reuses the existing `fieldforce.hitmap`
route (permission-gated `fieldforce.view`, visibility-scoped).

## 2. Seed demo corpus rebuilt — routed days instead of straight lines (CHANGED)

The old demo tracking data (R3/R7) drew a straight line per employee with
random jitter — no dwells at the visit locations, no unplanned stoppages, so
the hit map had nothing meaningful to show. The seed now generates, for the
**last 7 deployment-zone days** (idempotent, still marked `deviceId
"SEED-DEMO"`):

- **Routed itineraries** for EMP-0007 and EMP-0008:
  `home → visit A (dwell ~2h + COMPLETED visit) → unplanned tea-stall stop
  (20–40 min → amber "S" pin) → visit B (dwell + visit) → home`,
  with day-to-day time jitter so days don't look cloned;
- **matching VisitPlan + items + COMPLETED visits** (check-in/out coordinates
  pinned at the location, durations matching the dwell), plus EMP-0008's
  ad-hoc visit and EMP-0009's MISSED visit on yesterday (with a wandering
  trail that never reaches the planned stop);
- **GPS pings every ~3 min while moving** (street-level wobble, speed
  8–35 km/h) and **every ~4 min while dwelling** (±30 m wobble — inside the
  75 m stoppage-detection anchor so dwells are detected);
- leg times scale with distance so consecutive moving pings never land within
  the 75 m anchor (no phantom 3-minute stoppages — verified per-day);
- today's trail is capped at "now" so a freshly seeded database looks live;
  the four live-tracking states (TRACKING / OUTSIDE_GEOFENCE / LOW_BATTERY /
  TRACKING) now point at each employee's last real ping.

Result (verified in-browser): History shows 15 rows (7 days × 2 employees +
the missed day), each with GPS pings; the hit map for a demo day shows ~110
GPS fixes, ~16 km trail, 2 completed stops with durations (e.g. 2h 08m,
1h 48m), 1 unplanned stop, radius circles and the dotted polyline.

**Run it:** `bun run seed` (wipes and rebuilds the demo corpus — it is the
documented test seed, never run it against production data).
